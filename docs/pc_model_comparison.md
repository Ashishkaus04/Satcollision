# Probability-of-collision model comparison

_Generated by `scripts/run_pc_model_comparison.py`. Propagation window starts 2026-09-10T07:58:00+00:00._

## What is being compared, and what is held fixed

One Starlink catalogue (10,713 objects), propagated once with SGP4 across a 168-hour window at a 30-second step and screened once at 5 km. Every column below re-scores **that single set of conjunctions** — same epoch, same orbits, same candidate pairs, same regime sigmas, same threshold. Only the probability-of-collision estimator changes.

The paired table scores the encounters the **circular** model puts above threshold, so the columns describe the same physical encounters row by row. How many encounters each model admits on its own is reported separately, further down.

## Why four columns and not two

A Foster-vs-circular comparison moves for two independent reasons, and only one of them is the anisotropic covariance the model was built for. The other is that Foster scores the component of the separation perpendicular to the relative velocity, while the circular formula is handed the raw 3D separation at the closest *sampled* timestep and has no direction left to project with. The screening grid is 30 seconds wide, so a sample can sit well along the track from the true minimum, and all of that error is in the along-velocity direction.

| Column | What it is | What it isolates |
|---|---|---|
| `circular` | today's estimator, unchanged | the baseline every existing result uses |
| `circular-in-plane` | circular formula, projected miss | the projection / TCA-resolution effect |
| `foster(k=1)` | Foster, isotropic covariance | cross-checks the line above |
| `foster(k=8)` | Foster, along-track anisotropy | adds the anisotropy effect |

### How much the projection removes

Across 11835 screened conjunctions the in-plane miss is a median **0.835x** the raw miss (p10 0.356, p90 0.995, range 0.017-1.000). Through `exp(-d^2 / 2 sigma^2)` a shift of that size is not a rounding difference, which is why it has to be separated out rather than folded into an anisotropy claim.

## Which regime flags each encounter

The median gain above treats every encounter alike. Under a non-circular model that is misleading, because some encounters are flagged by only one regime, and the two cases mean opposite things:

- **Only cooperative flags:** precise tracking sees a real risk that public tracking never raises. Cooperation is the only way the operator hears about it.
- **Only no-cooperation flags:** the miss distance is large compared with precise tracking's uncertainty, so precise tracking correctly calls it safe, while degraded public tracking inflates the uncertainty enough to push Pc over the threshold. That is a false alarm: an unnecessary, fuel-costly manoeuvre that cooperation avoids. It shows up as a *negative* gain in the median above, which is why the median alone should not be quoted.

## Reading it

Under the circular model the median warning-time gain is **49.28 h**. Under the anisotropic model (`foster(k=8)`) the median over the same encounters is **0.00 h**, but that number mixes three different outcomes. Read the breakdown instead: where both regimes flag an encounter (81 of 237), cooperation still gives a median **19.13 h** more warning; in 73 more, cooperation's benefit is avoiding a false alarm rather than an earlier warning. The intermediate columns say how much of the move from the circular model is the projection and how much is the shape of the error ellipsoid; the report should quote that split and this breakdown, not the endpoints alone.

## Method notes

- Threshold 1e-04, screening horizon 72 h, combined sigma 0.5 km.
- Anisotropy is introduced at **constant trace**: `foster(k=8)` redistributes the same total uncertainty into the along-track axis rather than adding any, so the comparison isolates the shape of the error ellipsoid from its size.
- Every encounter row in the JSON carries `pc_model`, `raw_miss_m` and `miss_distance_m`, so a row can always be traced back to which column produced it.
